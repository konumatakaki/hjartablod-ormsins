# 台本の書き方（早見表）

台本は ink という形式で書く。ただし、使う記号は下の表の分だけでよい。
地の文と台詞は、ふつうの日本語の原稿とほぼ同じ書き方になる。

## 最小限の約束

| 書きたいもの | 書き方 | 例 |
|---|---|---|
| 内省（地の文） | ふつうに書く | （内省の文） |
| 台詞 | 名前と鉤括弧 | `リーダー「（台詞）」` |
| 通信（イヤホン越し） | 台詞の行末に `#通信` | `エンジニア「（台詞）」 #通信` |
| ルビ | 投稿サイトと同じ。`|` は半角でも全角でもよい。漢字だけの部分なら `|` は省略できる | `|椅子《いす》`、`椅子《いす》` |
| 用語の掘り下げ | 二重の角括弧 | `[[有気音]]` |
| Claude へのメモ | 行頭に `//` | `// ここで絵カードを見せる選択肢` |

`//` のメモは、ゲームの画面には出ない。自分用の覚え書きや、Claude への頼みごとに使う。

### 台詞の行の読み分け

ink 自体は話者を知らない。ink から見ると `リーダー「（台詞）」` もただの文字列で、ゲームの側がその行を読んで、話者の名札、通信の窓、内省の帯に振り分ける。

- 行の頭が「話者の名前＋「」で、その「」が閉じたところで行が終わるもの（後ろのタグは可）を台詞として扱う。それ以外の行は地の文（内省）。
- 地の文と台詞を1行に混ぜない。`私「（台詞）」と言った。` は台詞として切り出せないので、行を分ける。台詞の中の鉤括弧は『』にする。
- 話者は `tools/check-content.mjs` の `SPEAKERS` にある名前だけ（今は 私、リーダー、エンジニア）。少女の発話は日本語の台詞ではなく `#utter` で流す。
- 検査が、知らない話者、閉じていない「」、」の後ろに続く文を知らせる。

## 避けること

ink で特別な意味を持つ記号がある。地の文で使うと、文章として扱われなくなる。

- 行頭の半角の `*` `+` `-` `=` `~`（全角の罫線「──」で始まる行は問題ない）
- 文中の半角の `#` `{` `}` `->` `<>` `//`
- ルビ以外の場所の半角の `|`。ink では `{a|b}` のような分岐の区切りの記号なので、ルビの外で使うとエラーになる

### ルビと Inky

ルビの書き方は3通りあり、どれもゲームでは同じように表示される。

| 書き方 | Inky でそのまま使えるか | 備考 |
|---|---|---|
| `｜椅子《いす》`（全角の ｜） | 使える | Inky で書くならこれがいちばん楽。IME のユーザー辞書に「るび」→「｜《》」のように登録しておくと速い |
| `\|椅子《いす》`（半角の \| にバックスラッシュ） | 使える | ink の記号を文字として使うときの書き方（エスケープ） |
| `|椅子《いす》`（半角の \| だけ） | 公式版は使えない。改造版（下）なら使える | ゲームと検査では、ink に渡す前に全角に置き換えている（`tools/ink-preprocess.mjs`）。Inky はこの置き換えをしないので、エラーになる。Inky で確かめたいときは `npm run export:inky` で置き換え済みのコピー（`build/inky/`）を作って開く |

### Inky で半角の | のルビを使う（改造版の Inky）

Inky の設定の `customInkSnippets` は、カーソルの位置に決まった文字列を挿入するだけの仕組みで（Inky のソースで確認）、打った `|` を置き換えることはできない。
そこで、Inky がコンパイルの前にファイルを書き出す箇所に、ゲームと同じ置き換えを1か所挟む改造を用意した（`tools/inky/`）。元のファイルは書き換えず、行の数も変えないので、エラーの行番号はそのまま正しい。

**いちばん簡単な方法: 組み立て済みの改造版を落とす**

GitHub Actions（`.github/workflows/build-inky.yml`）が、改造版の Inky を Windows 向けに組み立てて、このリポジトリの「Releases」に置いている（ログイン不要）。

- **初めて入れるとき:** 最新の「改造版 Inky（ルビ対応）」の `Inky-win64-ruby.zip`（200MB 余り）を落として展開し、いつもの場所（`AppData\Local\Programs` など）に置いて `Inky.exe` を起動する。
- **更新するとき:** `Inky-ruby-app-asar.zip`（小さい）だけを落として、中の `resources\app.asar` で、入れてある Inky の `resources\app.asar` を上書きする。改造で変わるのはこのファイルだけ。
- `tools/inky/` を変えると自動で作り直され、古いリリースは消える。手動で作り直すときは、Actions の画面で build-inky を選んで「Run workflow」。
- 署名のない exe なので、初回の起動時に Windows が警告を出すことがある（「詳細情報」→「実行」）。

**手で組み立てる場合**

Windows での手順（ファイルを置き換えるだけで済む形。用意したものは `tools/inky/`）:

1. Node.js（LTS 版）を入れる（インストーラーで入る）。
2. Inky のソースを ZIP で落とす（https://github.com/inkle/inky の「Code」→「Download ZIP」）。好きな場所（たとえば `AppData\Local\Programs`）に展開する。
3. 展開したフォルダの `app\main-process\inklecate.js` を、このリポジトリの `tools\inky\inklecate.js` で上書きする。
4. `tools\inky\start-inky.bat` を、展開したフォルダ（`app` フォルダがある場所）に置いて、ダブルクリックする。初回だけ必要な部品を取ってくるので少し時間がかかる。2回目からはすぐ起動する。

- **注意:** GitHub の「Download ZIP」で落としたソースには、コンパイラ本体（`app\main-process\ink\inklecate_win.exe` と `inkjs-compatible\inklecate_win.exe`）が入っていない（Git LFS で別に管理されているため、中身のない目印のファイルになる）。公式の Inky のリリース版の `resources\app.asar.unpacked\main-process\ink\` から同じ名前のファイルをコピーして上書きする。
- 上書き用の `inklecate.js` は、2026年5月時点の Inky（3d46aa9）を元にしている。もっと新しい Inky に上書きすると、Inky 側の変更を消してしまうことがある。その場合は、差分（`tools\inky\inky-ruby.patch`）を当てる方法に切り替える（Git が要る）。
- 改造の中身は、Inky の `app/main-process/inklecate.js` の1か所。2026年5月時点の Inky に当たることを確認した。
- Releases の組み立て済みの改造版は、オーナーが Windows で動くことを確かめた（2026年10月）。手で組み立てる方法は、Windows ではまだ試していない。
- 改造版を使わない場合の代わり:
  - Inky の検索と置換（正規表現）で、遊ぶ前に一括で置き換える。検索 `(?<!\\)\|(?=[^|《》{}\n]+《)`、置換 `\|`
  - `customInkSnippets` で、`\|` を挿入するショートカットを作る（例は下）

```json
{
  "customInkSnippets": [
    { "name": "ルビの縦棒", "ink": "\\|", "accelerator": "CmdOrCtrl+Shift+R" }
  ]
}
```
（このファイルは `content/script/main.settings.json` として置く。Inky の README の「Project settings file」の書き方）

- 漢字だけの部分なら、どの書き方でも `｜` を省ける（`椅子《いす》`）。
- Inky の右側の画面では、ルビは記号のまま（`｜椅子《いす》`）表示される。ふりがなとしての見え方は、ゲームの画面で確かめる。

### 罫線とフォント

- 「──」は全角の罫線（U+2500）。ダッシュ（U+2014）と違って、並べたときに途切れずにつながる。
- つながり方は書体に依存するので、ゲームの書体はすべて同梱して固定する（design-rules.md）。

## 進め方

- 台本はオーナーが ink で直接書く。分岐も含めて。
- Claude は全部を読んで変換することはしない。代わりに:
  - 自動の検査（下の「検査」）で、ink の誤りと約束の違反を拾う
  - 頼まれた場面の骨組みを作る、頼まれた箇所を読んで直す
  - タグを増やす、エンジンの側で新しい演出に対応する

## 学ぶための資料

- ink の公式の解説: inkle の「Writing with ink」（英語）。https://github.com/inkle/ink/blob/master/Documentation/WritingWithInk.md
- 公式のエディタ Inky（無料。書きながら右側で遊べる）: https://github.com/inkle/inky/releases
- 色分け: Sublime Text 用の構文定義が inkle/ink のリポジトリにある（確度中）。Antigravity では拡張機能を「ink」で検索する。
- このプロジェクトで使うのは、まず次の4つで足りる: ノット（`=== 名前 ===`）、選択肢（`*`）、移動（`->`）、変数（`VAR` と `~`）。

## 検査

- `npm run check:content` で、台本が ink として正しく読めるか、タグ・話者・ルビ・用語の約束を守っているかを調べる（Node.js が要る）。
- GitHub に送ると、同じ検査が自動で走る。失敗すると、GitHub の画面に赤い × が付く。

### 書き方の見本

`content/script/sample.ink` を開く。実際に検査を通る見本で、選択肢、条件つきの選択肢、変数、通信の台詞、演出のタグを一通り使っている。文章の部分は括弧の空欄にしてある（Claude は台詞を書かない）。

## 使えるタグ（正本）

`#` で始まる演出の指示。増やすときは、この表と `tools/check-content.mjs` の `TAGS` を一緒に直す。

| タグ | 書き方 | 意味 |
|---|---|---|
| `#場面` | `#場面 日時 / 場所 / 状況` | 場面の見出し |
| `#通信` | 台詞の行末に `#通信` | イヤホン越しの通信として出す |
| `#show_card` | `#show_card: bread` | 絵カードを少女に見せる |
| `#utter` | `#utter: g_014` | 少女の発話（発話の番号）を流す |
| `#replay` | `#replay: g_014` | 録画の発話を聞き直す |
| `#layout` | `#layout: interview` など | 画面の配置を切り替える（名前は未定） |
| `#mind` | `#mind: memo` など | 内省の帯の状態を切り替える（open / memo / collapsed） |

```
  utterances/   少女の発話（ELAN の .eaf と、語彙の表）

```
