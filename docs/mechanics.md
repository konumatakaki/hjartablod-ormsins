# 操作のネタ帳

実際の言語学の操作を、その形を残したままミニゲームに落とす案。**すべて例。**

## 2つの層

- **作業の層:** ミニゲーム。本物の操作の形を借りて、証拠を作る。
- **推論の層:** 逆転裁判のループ。証拠を突きつけて、概念を獲得する。

概念の獲得は、道具の表示が一段増える形で見せられる（例: 「声調」という概念を得ると、転写にピッチの欄が増える）。
「表記の層」（premises.md）と同じ構造になる。

## 本物の操作 → ミニゲームの形

| 本物の操作 | 何をしているか | ミニゲームの形の案 |
|---|---|---|
| 分節 | 音の流れに切れ目を入れる | リズムゲーム。音節の境界で拍を刻む。少女の言葉遊び（音節の入れ替え）とも接続できる |
| 最小対 | 1か所だけ違う2語を見つけ、その違いが意味を区別するか確かめる | 間違い探し。2つのスペクトルを重ねて比べる |
| 音素の判定 | 2つの音が同じ音素か、異音かを決める | 仕分け。Papers, Please のハンコのように、許可・却下の要領で振り分ける |
| 形態素の分割 | 繰り返し出てくる断片を切り出す | 文を切り分け、共通する断片を揃えていくパズル（Chants of Sennaar に近い） |
| 活用表 | 形の変化を表にまとめる | 表の空欄を埋めるパズル |
| 構文木 | 語のまとまりと階層を見つける | 括弧や枝をドラッグして組み立てる |
| 声調 | ピッチの曲線を聞き分ける | 曲線をなぞる、または合わせる |
| 聞き取り | どう質問すれば欲しい情報が出てくるか | 会話の選択肢。逆転裁判の「ゆさぶる」に近い |
| 対応付け | 語と意味、または語と語を結びつける | 線つなぎ |

## 精度のバーと、層どうしの循環（オーナー案）

- 汎用の音素認識でも、ある程度の発音データがあり、ファインチューニングすれば、それなりに取れるようになる。
- 層ごとにバーがあり、溜まると次の層に進める。次の層での作業が、前の層の精度を上げる。
- どこまで現実に寄せるか（リアリティライン）次第で、細部は変わる。

### 現実との対応（Claude）

- **少量のデータで精度が上がるのは現実の話。** wav2vec 2.0 の論文では、10分程度の書き起こし付き音声でのファインチューニングでも、それなりに使える結果が出ている（確度高）。
- **上の層が下の層を助けるのも現実の話。** 形態素が分かると、どの音の揺れが意味を区別しないかが分かる（形態音韻論）。実際の分析も、層を行き来しながら進む。
- **転写が増える → モデルが良くなる → 転写が楽になる、という循環は、実際の低資源言語の書き起こし作業で使われる方法（ブートストラップ）。**

### 設計の案（Claude）

- **バーが頭打ちになること自体を、手がかりにする。** たとえば声調という概念がないままだと、音素認識の精度は一定以上に上がらない。誤りは、声調で区別される語に集中する。
  「バーが80%から動かない」ことが、何かの概念が欠けているという証拠になる。突きつけの材料にできる。
- **話し方の切り替えで精度が落ちるのは現実の話。** 丁寧に読み上げた音声で学習したモデルは、くだけた自発的な会話で精度が大きく落ちる（確度高）。
  くだけた話し方では、音が弱まったり脱落したりして、母音や子音の実際の発音の幅が広がる（Lindblom の H&H 理論。はっきり話すか、手を抜いて話すかの連続体）。
  厳密には「過学習」より「ドメインシフト（学習時と使用時のデータの性質のずれ）」が近い。
  言語学者の主人公が分野外の用語を緩く使い、機械学習の側のエンジニアが正す、という形なら「専門家は専門用語を正しく使う」の線と両立する。
- **作業の繰り返し（グラインド）にしない。** 逆転裁判に、同じ作業の繰り返しはない。バーは、意味のある行動（新しい発話を引き出す、矛盾を崩す）で溜まるようにする。

## 登場人物とゲームの機能（Claude 案）

| 人物 | ゲーム上の機能 |
|---|---|
| 主人公 | プレイヤー。見せる、突きつける |
| リーダー | 進捗の管理とヒント（逆転裁判で助手が出すヒントの役）。1日の終わりの報告書 |
| エンジニア | 道具の追加と、道具の出力を疑う手伝い |

- **1日の終わりの報告書:** リーダーが書く日報を、章の終わりのまとめ画面にする。
  その日に獲得した概念、崩れた仮説、精度のバーの推移を、コンサルの報告書の文体で書く。
  言語学と死後の世界の話が、人事の業務報告の文体で書かれている、という文体のずれも笑いになる。

## 1日の体験の流れ（Claude 案）

体験の柱:

1. **観察:** 記録装置越しに少女を見る。字幕が表記の層に応じて変わる。
2. **操作:** 道具を使い、ミニゲームで証拠を作る。
3. **推理:** 仮説と証拠の矛盾を見つけ、突きつけて、概念を獲得する。
4. **読む:** 内省、会話、ブリーフィング、報告書。

1日（1話）の流れ:

| 段階 | 主な柱 | 画面の配置 |
|---|---|---|
| 移動とブリーフィング | 読む | 暗い背景＋会話、組織の資料 |
| 収録前の点検 | 観察 | 仮想マシン（起動の演出） |
| 聞き取り（1回目） | 観察、操作（見せる） | 仮想マシン（カメラの窓を大きく） |
| 休憩と分析 | 操作、推理 | 仮想マシン（道具の窓を大きく） |
| 聞き取り（2回目以降） | 観察、推理（突きつける） | 仮想マシン |
| 食堂、廊下、宿 | 読む | 暗い背景＋会話か地の文 |
| 報告書 | 読む（振り返り） | リーダーの報告書 |

- 時間は、読むことと選ぶことで進む。プレイヤーが移動を操作することはない（ここはノベルゲームの体験）。
- 読む量と操作する量の比率は未定。

## 文字と時間を作中の媒体に置き換える（Claude 案）

「ノベルの機能」（文字送り、履歴、選択肢、セーブ）という括りで考えない。
このゲームで文字が出る場所と、時間が進む仕組みを、作中の媒体として設計する。

| ノベルゲームの機能で言うと | このゲームでは | 作中の媒体 |
|---|---|---|
| 文字の窓 | 字幕、内省、チームとの会話、資料。種類ごとに出る場所と見た目が違う | 音声認識の字幕、主人公の頭の中、車内や廊下の会話、組織の資料 |
| 履歴（バックログ） | **録画のタイムラインを巻き戻す。** 少女の発話は、いつでも聞き直し、読み直せる | 録画と、その書き起こし |
| 内省の履歴 | 主人公のフィールドノート | ノート |
| 選択肢 | 何を見せるか、何を尋ねるか、何を突きつけるか。メニューの分岐ではなく動詞 | 小道具、質問、証拠 |
| セーブ | 聞き取りの区切りと、1日の終わりで自動的に記録する | 録画のファイル、リーダーの報告書 |

### 録画のタイムラインと表記の層は同じもの

- 言語学の注釈ソフト ELAN は、録画の時間軸の上に、複数の注釈の段（tier）を重ねる。音声、書き起こし、グロス、自由訳などを段ごとに持つ（確度高）。
- これは「表記の層」とそのまま同じ構造になる。字幕は、再生中の時刻にある各段の注釈を表示したものにすぎない。
- 概念を獲得すると、段が増える。録画を巻き戻すと、昔の発話も新しい段で読み直せる。昔は「███」だった発話が、IPA で読めるようになっている。
- 履歴、字幕、表記の層、証拠の出どころが、1つの仕組みにまとまる。

## 聞き取りの時間の流れ（確定）

- **1発話ずつ進む。** プレイヤーの操作を待って、次の発話に進む。
- 演出上は、主人公が十分に賢いので、思い出したりタイムラインを巻き戻したりを、ほぼ実時間でこなしている、という扱い。
- ノリは逆転裁判に近い。

### Claude の整理

- 作中の時間では、発話と発話の間にプレイヤーが考えている時間は、主人公の一瞬の思考にあたる。聞き取りの最中に考える時間の罰はない。時間の圧力は1週間という単位でだけかかる。
- 巻き戻しの演出: タイムコードが跳ぶ、波形が逆に流れる、など短く見せる。主人公の頭の速さの表現にもなる。
- 逆転裁判との対応:

| 逆転裁判 | このゲーム |
|---|---|
| 証言の1文 | 録画の1区間（1発話） |
| 尋問（証言を順に見直す） | 録画の区間を順に聞き直す |
| ゆさぶる | その区間について、さらに尋ねる（次の聞き取りで引き出す） |
| つきつける | その区間に、証拠（道具の出力、別の区間、小道具への反応）を突きつける |

- データの単位も1発話になる。1発話 = 録画のタイムライン上の1区間で、表記の層ごとの注釈を持つ。ink は、どの発話が次に来るかと、発話の間にプレイヤーができることを決める。

## 規模の注意

ミニゲームは種類ごとに実装の手間がかかる。半月で作るなら、まずは1〜2種類で作る。
