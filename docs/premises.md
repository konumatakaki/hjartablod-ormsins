# 前提と決定事項

このプロジェクトの土台になる決定をまとめる。細部は各文書へ（末尾の「文書の地図」）。
チャットは長くなると要約されて細部が消えるので、決まったことはここか各文書に書く。

状態: **確定** / **仮**（議論中だが当面これで進む）/ **未定**（open-questions.md へ）。ほかの文書で使う **決定** は確定と同じ、**案** は Claude の案で未確認、**空欄** は未定と同じ。

## 1. 動機

- 言語を深く扱う作品（『あなたの人生の物語』）は、解読の道具の描写が薄い。道具を出す作品（『プロジェクト・ヘイル・メアリー』）は、言語を暗号のように扱う。両方を満たす作品がない。このゲームはそこを埋める。
- 一文で言うと: **道具は濃く見せ、言語は暗号として扱わない。**
- 中心になる問い: **現代の道具で、接点の少ない言語を解読するとどうなるか。**
- 扱う範囲: 言語学と言語哲学の、それなりに広い範囲。

### 言葉の注意

- 初期の会話で使った「ノベルゲーム」という言葉は、体験の一部（読むこと、時間が読むことと選ぶことで進むこと）を指していた。**ジャンルの枠や、技術の選択の根拠としては使わない。**
- 文書の中のオーナーの言葉は、意図が伝わる一般的な言い方に置き換えてよい。言い回しそのものに意味がある場合だけ、引用として残す。

## 3. 狙い

- **体験の中心は雰囲気。** 記録装置と道具越しに一人の人間と向き合う手触り。パズルの難しさで引っ張らない。
- **「言語解読ゲーム＝推理パズル（言語学オリンピック型）」という型を、道具の側を強調することで崩す。**
- **描くのは概念の獲得と分析。** 作業そのものではない。
- **操作の形は本物の言語学から借り、手間は抽象化する。** 厳密な照合である必要はなく、リズム、仕分け、並べ替えのような遊びでよい。実際の操作に似ていることが望ましい（mechanics.md）。
- **道具は本物らしく見せる。** 本物らしく見えればよく、必ずしも本当に計算しなくてよい。安く本物にできるところ（少女の声のスペクトルをその場で計算するなど）は本物にする。
- **少女の発話は、できれば実際の音声で用意する。**
- 方向性の参考:
  - 演出: 映画『メッセージ（Arrival）』の解析画面（Wolfram 親子が実際にコードを書いた）
  - UI の手触り: Papers, Please、Hacknet
  - 雰囲気のベクトル（直接は出ない）: ロールプレイに寄せて遊んだ FTL（乏しい情報と短い文から物語を補う）、In Other Waters（世界は計器越しにしか見えず、人間の言葉が計器に色を付ける）、KSP の打ち上げ時の画面（数字に物理的な理由があり、計器を見守ること自体が緊張になる）
  - 類似作品から踏襲するアイデア: references.md

## 4. 体験の核

### 4.1 逆転裁判の構造を借りる（確定）

- 矛盾を見つけて突きつけ、そこから生まれた新しい謎の中で、また矛盾を探す。
- **証言**にあたるもの: 録画の1区間（少女の1発話）と、登場人物の翻訳・仮説・思い込み。
- **証拠**にあたるもの: 道具の出力（スペクトル、統計、表記）、別の区間、小道具への反応。
- プレイヤーは頭の中で解読するのではなく、**道具を操作して、主張と食い違う出力を選んで突きつける**。
- **主人公は少女の前で日本語を使わない**（上からの縛り。名前は可）。聞き取りは、少女の発話をまねて返す、名前、身振り、絵カードで行う（characters.md）。
- 聞き取りは**1発話ずつ**進む。主人公が十分に賢く、思い出すことも巻き戻すこともほぼ実時間でこなしている、という演出。時間の圧力は1週間という単位でだけかかる。
- 細部（尋問、ゆさぶる、つきつけるの対応）: mechanics.md

### 4.2 体験の柱

1. 観察: 記録装置越しに少女を見る。
2. 操作: 道具を使い、証拠を作る。基本の動詞は「見せる」（小道具で発話を引き出す）と「突きつける」（証拠で仮説を崩す）（仮。open-questions.md A1）。
3. 推理: 仮説と証拠の食い違いから、概念を獲得する。
4. 読む: 内省、会話、ブリーフィング、報告書。

文字が出る場所と時間の進み方は、作中の媒体（録画、ノート、資料、1日の区切り）として設計する。汎用の「文字の窓、履歴、選択肢、セーブ」という部品の考え方はしない（mechanics.md）。

### 4.3 表記の層と録画のタイムライン（確定。細部は仮）

解読の進み具合を、言語をどの解像度で表記できるかで見せる。

0. 伏せ字「███」（長さだけ）
1. スペクトル（音そのもの）
2. 精密表記の IPA `[ ]`
3. 音素表記 `/ /`
4. ラテン文字への転写
5. 形態素分割とグロス（ライプツィヒ・グロス規則）
6. 構文木など

- 構造は言語学の注釈ソフト **ELAN** を踏襲する。録画の時間軸の上に、注釈の段（tier）を重ねる。表記の層は段の種類として表す。
- 字幕は、再生中の時刻にある段の注釈を表示したもの。録画を巻き戻すと、昔の発話も新しい段で読み直せる。
- 層を上がるごとに情報が捨てられる。下の層に戻ると、上の層の間違いの証拠が残っている。
- **安易な日本語の直訳は出さない。** 自由訳（日本語訳）は道具の出力としては出さず、登場人物が仮説として口にする（確定）。
- 0段目「███」の出どころ: mechanics.md の「伏せ字の出どころ」（案）。

### 4.4 道具の能力（確定）

- **道具は証拠を出す。結論は出せない。** 設計上の制限ではなく、現代の技術の事実として扱う。
- 万能の翻訳 AI はない。方向性を決めれば、それなりの言語カード（聞き取り用の小道具一式）や分析を出せる。パターンが分かれば、音声から構文木を自動で作れる（精度は不明）。
- 現代の道具は、仮説を増幅する装置。間違った仮説で動かすと、もっともらしく間違った証拠を出す。
- 結論らしきものを出す道具（翻訳 AI など）は、信頼できないものとして登場する。
- 詳細: tools.md

### 4.5 専門用語の注釈（確定。細部は仮）

- 主人公の内省には、専門用語がそのまま出てくる。
- 専門用語は色を変えて表示する。クリック（タップ）で開くと、主人公がプレイヤー向けに思考を深めてくれる。注釈の中の用語にも注釈がある（Paradox 社のゲームのヘルプのような入れ子）。
- ホバーは補助にとどめ、必須にしない。
- 用語集は別のファイルにして、オーナーが直接編集できるようにする。

## 5. 世界と人物の描き方

### 5.1 世界のルール（設計上の公理）

- 少女はホモ・サピエンスである。
- 音声言語は線状性を持つ（Saussure）。
- 少女の言語は、普遍文法の枠組みで分析できる。ここでの普遍文法は、「それなりに拡張でき、たいていの情報伝達の概念を詰め込める便利な袋」くらいの意味。
- 弱いサピア＝ウォーフ仮説は成り立つ（言語は思考に影響するが、決定はしない）。
- 少女は文字を知らない。

普遍文法の存在は現実の学界では争われている（Evans と Levinson の批判、Everett のピダハン語をめぐる論争など）。ゲームの中では公理として扱い、登場人物の議論の種にはしうる。

### 5.2 少女の描き方（確定）

- 「遅れた文明の人間」としては描かない。
- 少女は、自分の前提（ここは死後の世界）のもとで筋の通った解釈をしている。驚くより、「そういうものだ」と納得したうえで、我々から見て誤解している。
  - 鏡があるなら、前世が映るのだろうと思っている。
  - 絵が動いても、すぐに順応する。
  - チームを、巡察に来た聖職者や寄進の調整に来た領主のような「大変そうな偉い人」として見ている。
- 背景の知識:
  - 中世ヨーロッパの教会には、司教が修道院や教区を回って規律を調べる巡察（visitation）の制度があった。少女にとっての死後の審判は、畏怖の対象より、こういう手続きの延長として描ける。チーム側も倫理委員会に書類を出す組織なので、両側とも官僚的な手続きを生きている。
  - 人類学では、フレイザーの「呪術 → 宗教 → 科学」という進化論的な見方は、Evans-Pritchard のアザンデの妖術研究（1937年）などで覆された。前提を共有すれば、信念の体系は内側から見て合理的だという見方。
  - 閻魔の庁には、死者の生前の行いを映す浄玻璃の鏡がある。死後の審判と行いを映す鏡の結びつきは、現実の宗教にも見られる。

### 5.3 専門家の描き方（確定）

- **専門家は、専門用語を正しく使う。** そのうえで、派閥の癖や、内輪の論争の中での立ち位置はある。
- 知識の水準の目安: 言語学者なら、SEP の "Philosophy of Linguistics" の項目を下敷きに、しばらく議論できる程度。その項目は言語学の立場を外在主義、創発主義、本質主義の3つの傾向で整理している。
- 素朴さは用語の誤用ではなく、**自分の分野や派閥の前提が死角を作る**形で出す。
- 素朴さの向きは分野をまたぐと対称になる。言語学者は文化や宗教について古い見方を持ちがちで、人類学者は言語学について古い見方を持ちがち。作中では主に、言語学者の主人公の素朴な概念を、文化人類学者のリーダーが正す。
- 分野外の用語を緩く使うことはありうる。その場合は、その分野の専門家が正す。

## 6. 進め方

### 6.1 役割

| 領域 | 決める人 | Claude の役割 |
|---|---|---|
| ゲームの核、世界観、人物、本文 | オーナー | 下書き、設定の整理、矛盾の確認 |
| 架空言語 | 共同 | 言語として破綻しない設計 |
| UI、見た目 | オーナー | 見本を作り、実装する |
| 技術の選択、実装、公開 | Claude（オーナーが承認） | ほぼ全部 |
| 進行管理 | 共同 | この docs を管理する |

- オーナーには文章執筆の経験があり、本文を直接書くこともある。そのときの Claude の役割は、雰囲気を保ったまま誤字・脱字を拾うことと、トーンを言葉で説明すること（style.md）。
- オーナーは Python を最低限読み書きできる。実装は Claude が担当し、仕組みは共有する。

### 6.2 実装の共有

- 内容（台本、用語集、語彙、表記の層の注釈、画像、音声）とエンジンを分ける。内容は、コードを触らずに編集でき、ブラウザの再読み込みで確認できる。
- 台本は ink で書く。
- 内容の検査は Node（`tools/check-content.mjs`。ink の翻訳に inkjs を使うため）。見本の組み立てや画像の処理は Python。
- ブラウザ側のコードの仕組みは、docs で文章として説明する。
- オーナーだけで続けられる状態は「あると良い」程度（半月後も Claude Code は使える）。

### 6.3 話し方（確定）

- 常体で話す。結論を先に言う。前置きと褒め言葉は省く。
- 反対意見ははっきり言う。同意するためだけの同意はしない。
- 確かな知識、推測、好みを区別して書く。
- 質問は一度に3つまで、優先度の高い順に。
- オーナーは返事を詳しく書く。曖昧なところはお互いに詰める。
- 分からないことがあるのは問題ない。片方が知っていればそれで対応し、どちらも知らなければ調べるか試す。
