# UI の検討

未決。オーナーが悩んでいる段階。

## 候補（オーナー）

- **A. アクリル板越しの様子と、手元のパソコン**: 画面を上下か左右に分ける（Papers, Please 型）
- **B. 少女の顔の周りに、各種のアイコンが浮かぶ**: AR 的な重ね表示（過去作の BIFRONS のサングラスに近い）
- **C. 完全にデスクトップで閉じる**: 画面全体がノートパソコンのデスクトップ（Hacknet 型）

## 参考作品（Claude）

- **Her Story（2015）**: 古いパソコンのデスクトップで、警察の取調べの映像を検索して見ていく。
  「取調べの映像をデスクトップ越しに見る」という点で、C 案にかなり近い。同じ作者の Telling Lies も。
- **Papers, Please**: 上が外の世界、下が机。A 案の元型。
- **逆転裁判**: 会話の画面と法廷記録の画面を切り替える。

## 判断材料（Claude）

- **B の AR 表示は、時代設定と合わない。** 現代くらいの設定では、AR グラスは浮く。
  ただし、カメラ映像の上に顔の特徴点やアイコンを重ねる表示（MediaPipe などで実際にできる）なら現代的。B は、A か C の中のカメラ映像の窓に吸収できる。
- **C のデスクトップは、主題（道具を濃く見せる）に一番合う。** 少女の顔もカメラ映像の窓の中に映る。
  「彼女を道具越しにしか見ていない」ことが、画面の構造そのもので表現される。ブラウザは窓や表の UI が得意なので、実装とも相性がいい。
- **C の弱点は、雰囲気と立ち絵。** 楽しみの中心は雰囲気。立ち絵（目線や手振りの差分を含む）を大きく見せたい場面では、窓の中だと小さい。
  地の文（内省）をどこに出すかも問題になる。
- **「見せる」の操作は、どの案でも成り立つ。** 部屋には少女向けのディスプレイがあるので、画像をそちらに送ればいい。

## Claude の推し: A と C を切り替える

- **面接の画面**: アクリル板越しの少女（大きな立ち絵）＋テキストの欄＋小さな道具の表示。物語と雰囲気の場面。
- **解析の画面**: ノートパソコンのデスクトップ全体。スペクトル、表記の層、ミニゲーム、辞書。
- 2つを行き来するリズムは、実際のフィールドワークの「聞き取りの時間と、休憩中の分析」に対応する（過去作でも休憩のタイマーがあった）。1日（1話）を、何回かの聞き取りと分析の繰り返しで組み立てられる。
- 解析の画面にも、少女の顔はカメラ映像の窓として残す。B の重ね表示は、この窓の上で行う。

## オーナー案: 面接もカメラ映像として見せる（仮）

これで、すべてがデスクトップの中に収まる。面接の画面は「カメラ映像の窓を最大化した状態」、解析の画面は「窓を並べた状態」になる。

### Claude の補足

- **画面の物語上の正体:** 録画ソフトのプレビュー。REC の表示、タイムコード、音量メーター、顔の特徴点の重ね表示が付く。
  プレイヤーは最初から「記録装置越しに」少女を見ている。
- **字幕が表記の層になる。** 少女の台詞は、書き起こしの道具が出す字幕として表示する。
  最初は「███」で長さだけ。層が解放されると、同じ字幕がスペクトル、IPA、転写、グロスへと変わる。
  チーム側の日本語は、音声認識の字幕として正確に出る。その対比自体が状況説明になる。
- **内省（地の文）は、カメラの枠の外に出す。** 字幕（記録されたもの）と内省（記録されないもの）を見た目で分ける。
- **AI で生成した絵の揺れを、カメラのフィルターでならせる。** 色調、粒子、レンズの歪みを全画像に共通でかければ、NovelAI の出力の画風のばらつきが目立ちにくくなる。制作上かなり助かる。
- **カメラが複数あると、それ自体が道具になる。** 顔の正面のカメラと、全身が映る広角のカメラ。
  目線や手振りのアノマリーは、広角に切り替えないと見えない。
- **少女はカメラに気づく。** 鏡と同じように、彼女なりの意味づけをしてカメラに話しかけてくるかもしれない。
- **実装:** 画面の配置の仕組みが1つで済むので、2つの画面を作り分けるより簡単になる。
