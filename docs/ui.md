# UI の検討

未決。オーナーが悩んでいる段階。

## 候補（オーナー）

- **A. アクリル板越しの様子と、手元のパソコン**: 画面を上下か左右に分ける（Papers, Please 型）
- **B. 少女の顔の周りに、各種のアイコンが浮かぶ**: AR 的な重ね表示（過去作の BIFRONS のサングラスに近い）
- **C. 完全にデスクトップで閉じる**: 画面全体がノートパソコンのデスクトップ（Hacknet 型）

## 参考作品（Claude）

- **Her Story（2015）**: 古いパソコンのデスクトップで、警察の取調べの映像を検索して見ていく。
  「取調べの映像をデスクトップ越しに見る」という点で、C 案にかなり近い。同じ作者の Telling Lies も。
- **Papers, Please**: 上が外の世界、下が机。A 案の元型。
- **逆転裁判**: 会話の画面と法廷記録の画面を切り替える。

## 判断材料（Claude）

- **B の AR 表示は、時代設定と合わない。** 現代くらいの設定では、AR グラスは浮く。
  ただし、カメラ映像の上に顔の特徴点やアイコンを重ねる表示（MediaPipe などで実際にできる）なら現代的。B は、A か C の中のカメラ映像の窓に吸収できる。
- **C のデスクトップは、主題（道具を濃く見せる）に一番合う。** 少女の顔もカメラ映像の窓の中に映る。
  「彼女を道具越しにしか見ていない」ことが、画面の構造そのもので表現される。ブラウザは窓や表の UI が得意なので、実装とも相性がいい。
- **C の弱点は、雰囲気と立ち絵。** 楽しみの中心は雰囲気。立ち絵（目線や手振りの差分を含む）を大きく見せたい場面では、窓の中だと小さい。
  地の文（内省）をどこに出すかも問題になる。
- **「見せる」の操作は、どの案でも成り立つ。** 部屋には少女向けのディスプレイがあるので、画像をそちらに送ればいい。

## Claude の推し: A と C を切り替える

- **面接の画面**: アクリル板越しの少女（大きな立ち絵）＋テキストの欄＋小さな道具の表示。物語と雰囲気の場面。
- **解析の画面**: ノートパソコンのデスクトップ全体。スペクトル、表記の層、ミニゲーム、辞書。
- 2つを行き来するリズムは、実際のフィールドワークの「聞き取りの時間と、休憩中の分析」に対応する（過去作でも休憩のタイマーがあった）。1日（1話）を、何回かの聞き取りと分析の繰り返しで組み立てられる。
- 解析の画面にも、少女の顔はカメラ映像の窓として残す。B の重ね表示は、この窓の上で行う。

## オーナー案: 面接もカメラ映像として見せる（仮）

これで、すべてがデスクトップの中に収まる。面接の画面は「カメラ映像の窓を最大化した状態」、解析の画面は「窓を並べた状態」になる。

### Claude の補足

- **画面の物語上の正体:** 録画ソフトのプレビュー。REC の表示、タイムコード、音量メーター、顔の特徴点の重ね表示が付く。
  プレイヤーは最初から「記録装置越しに」少女を見ている。
- **字幕が表記の層になる。** 少女の台詞は、書き起こしの道具が出す字幕として表示する。
  最初は「███」で長さだけ。層が解放されると、同じ字幕がスペクトル、IPA、転写、グロスへと変わる。
  チーム側の日本語は、音声認識の字幕として正確に出る。その対比自体が状況説明になる。
- **内省（地の文）は、カメラの枠の外に出す。** 字幕（記録されたもの）と内省（記録されないもの）を見た目で分ける。
- **AI で生成した絵の揺れを、カメラのフィルターでならせる。** 色調、粒子、レンズの歪みを全画像に共通でかければ、NovelAI の出力の画風のばらつきが目立ちにくくなる。制作上かなり助かる。
- **カメラが複数あると、それ自体が道具になる。** 顔の正面のカメラと、全身が映る広角のカメラ。
  目線や手振りのアノマリーは、広角に切り替えないと見えない。
- **少女はカメラに気づく。** 鏡と同じように、彼女なりの意味づけをしてカメラに話しかけてくるかもしれない。
- **実装:** 画面の配置の仕組みが1つで済むので、2つの画面を作り分けるより簡単になる。

### カメラの位置（確定）

- メインのカメラは正面から。
- 場合によっては、Blender で部屋のモックアップを作る（今すぐではない）。

## 「とにかく雑に突っ込まれた、スペック重視の仮想マシン」の見た目（Claude 案）

エンジニアがその場で立ち上げた Linux の仮想マシン、という体裁。

### 構成要素

- **タイル型のウィンドウマネージャ（i3 や sway の類）**: 窓が重ならず、画面を隙間なく分割して並ぶ。
  エンジニアの実用本位の環境として現実味がある。固定画面にも合い、CSS のグリッドでそのまま作れる。
- **上端のステータスバー**: CPU と GPU の使用率、VRAM、温度、時計、ネットワークは「OFFLINE」。
  解析を走らせると GPU の使用率が跳ね上がる。スペック重視を見せる一番安い方法。
- **道具は localhost のウェブアプリ**: ヴァイブコーディングで作られる機械学習の道具は、たいてい Gradio や Streamlit の画面になる（確度高）。
  ブラウザのタブに `localhost:7860` が並び、どれも初期テーマのまま。新しい道具の追加は、新しいタブが増えることで表現できる。
- **端末の窓**: エンジニアのエージェントが流すログ（`pip install`、`git pull`、学習の進捗）。道具が追加されるときに流れる。
- **Jupyter ノートブック**: 主人公が自分の分析をする場所。librosa を import するのが見える。
- **ファイルの一覧**: `session_001.wav` のような録音、`final_v2_really_final.py` のような雑な名前のファイル。

### 現実味のある小ネタ

- 日本語のフォントが入っていない最小構成の仮想マシンでは、日本語が「□□□」（いわゆる豆腐）で表示される（確度高）。
  エンジニアがフォントを入れるまで日本語が化ける、という導入にできる。
- IPA の記号自体は一般的なフォントでもおおむね表示できるが、発音区別符号を重ねると表示が崩れることがある（確度中）。
  SIL の Doulos SIL や Charis SIL は、IPA の表示のために作られた実在のフォント。

### デザインの原則（案）

- **飾るのは道具の出力だけ。** 仮想マシンの外枠は、初期設定のままの暗い灰色と等幅フォントで地味にする。
  色があるのは、スペクトログラムの虹色や精度のバーのような、データだけ。プレイヤーの目が自然にデータに向かう。
- **何も隠れない。** タイル型なので窓が重ならず、必要な情報が常に見えている（Papers, Please の机と同じ考え方）。

## モックとデザインの前提（確定）

- それは、まあまあリアルでなくてはならない。
- それは、そこまでクールであってはならない。無骨な機能美。
- AI の手癖を出さない。ある程度進んだら、デザインのルールを決める。
- アイコンとフォントは統一する。
- 起動画面はリアルにする。なんとなくの文字ではなく、**その文字がそこにある理由**をちゃんと詰める。

### Claude の整理: 文字の理由の出どころ

画面上のすべての文字、色、アイコンには、次のどちらかの出どころを持たせる。

1. **初期設定。** OS、ウィンドウマネージャ、ライブラリの初期値そのまま。初期値は、定義上クールではなく、定義上リアル。
2. **誰かが変えた理由。** エンジニアや組織が、必要があって変えたところ。変更点は少なく、それぞれに理由がある。
   （例: 機密を扱うのでディスクを暗号化している → 起動時にパスフレーズの入力がある。ネットワークを禁止されている → 無線の起動に失敗する行が出る）

そのために、先に**マシンの設定資料**（小道具の設定資料）を作る。
ディストリビューション、カーネル、ウィンドウマネージャ、GPU、CUDA、Python と主要ライブラリの版、ホスト名、ユーザー名、起動の流れ。
起動ログ、ステータスバー、窓のタイトル、ファイル名は、すべてこの資料から導く。

### Claude が出しがちな手癖（避けるもの）

自分の傾向として自覚しているもの。

- 紫から青へのグラデーション、すりガラス風の半透明、角丸のカードと柔らかい影
- 絵文字をアイコン代わりに使う
- ネオン緑の「ハッカー」風の文字、ACCESS GRANTED、意味のない16進数の羅列
- 意味のない「ANALYZING...」の文字や、何も表していない進捗表示
- 何でも中央寄せ、何でも大文字の等幅のラベル
- 根拠なく Inter や Roboto を使う
- アイコンの出どころを混ぜる

### 現実の初期値の例（確度は記載のとおり）

- i3 の初期設定の配色: フォーカス中の窓のタイトルバーは青系（#285577 など。確度高）。フォントは `pango:monospace 8` 相当の小さな等幅。
- Gradio は初期ポート 7860、Streamlit は 8501（確度高）。どちらも初期テーマのまま使われがち。
- フォントの候補: DejaVu Sans Mono、Noto Sans Mono、Noto Sans CJK JP、IPA 用に Doulos SIL か Charis SIL。
  いずれも自由なライセンス（SIL Open Font License など）で、無料のゲームに同梱できる。
- アイコン: Linux の既存のアイコンテーマ（GNOME の Adwaita、Papirus など）から1系統だけ選ぶ。ライセンスの確認は要る。

### リアリティの確認事項

- **本当に仮想マシンか。** 機械学習で GPU を使うなら、仮想マシンでは GPU をそのまま渡す設定（パススルー）が面倒。
  現実のエンジニアなら、ノートパソコンに Linux を直接入れて、コンテナで環境を分けることが多い（確度中〜高）。
  「雑に突っ込まれた」感じを出すなら、どちらでも作れる。仮想マシンにするなら、パススルーで苦労した痕跡そのものがネタになる。

## 見た目の方向（決定: (a) ベース）

- (a) 平らで暗い最小構成（dwm 系）を土台にする。ミニマムなアイコンを付ける。
- 見本: `mock/ui-swatches.html`（生成元は `mock/src/`）

### 書体（見本の第2版での整理）

前の版が「作り物っぽく、安っぽく」見えた原因（Claude の分析）:

1. 指定した書体（DejaVu Sans Mono）が見る側の環境に入っておらず、日本語書体の英字に落ちていた。
2. 文字サイズを画面幅に比例させたので、端数のピクセルになって輪郭がぼやけていた。
3. 書体の出どころが、設定資料と無関係にばらばらだった。

対策: 画面は 1280×720 の固定解像度で、整数の文字サイズで組み、全体を縮小する。書体は初期設定から導いて同梱する。

| 場所 | 書体 | 理由 |
|---|---|---|
| dwm のバー | DejaVu Sans Mono 13px | dwm の初期設定 `monospace:size=10`。Ubuntu では monospace が DejaVu Sans Mono になる |
| 端末（st） | Liberation Mono 12px | st の初期設定 `Liberation Mono:pixelsize=12` |
| ブラウザの中の道具（Gradio） | Source Sans Pro | Gradio 6 が書体を同梱しているので、オフラインでもこれで出る（実機で確認。当初の「既定の sans に落ちる」は誤り） |
| 日本語 | Noto Sans JP | Ubuntu の日本語書体 fonts-noto-cjk と同じ字形 |

- ライセンスの注意: Liberation フォントは SIL OFL で、「Liberation」が予約書体名になっている。使う文字だけに絞った版（改変版）を配布するなら、名前を変える必要がある。最終版では、改変しない元のファイルを同梱するか、名前を変える。DejaVu は改変版の配布に名前の制約がほぼない（Bitstream Vera の名前を使わなければよい）。
- 残る差: Linux はヒンティングで輪郭を画素に合わせるが、Mac のブラウザはしない。

ルールとしてまとめたものは `design-rules.md`（仮）。

### 窓ごとの見た目の違い（確定）

- 窓ごとに感じが違うのはあり。程度による。チグハグ感があってもよい。
- 右下（ブラウザの中の道具）は、多少モダンな感じでもよい。
- （Claude の整理）**チグハグさは、出どころの違いから生まれるものに限る。** 窓の中は、それぞれの出どころ（ソフトの初期設定）で一貫させる。
  - 土台の dwm と st: 古くて最小
  - ヴァイブコーディングで作られた道具（Gradio）: 一番新しい層なので、一番モダン
  - 現実のデスクトップも、作られた時代も部品も違うソフトの寄せ集めなので、このチグハグさ自体がリアル。
- （Claude 案）録画の窓が OpenCV の窓なら、映像の上の文字（REC、タイムコード）は OpenCV の putText で描かれ、Hershey という線画の書体になる。
  putText は日本語を描けない（ASCII のみ。確度高）ので、日本語の字幕は別の仕組みで描いている、という理由も付く。

### 起動の演出（方針は確定、中身は案）

- オーナー: 起動のときに、それらしい演出が欲しい（顔と目の位置合わせ、腕や手の上に走るボーン）。ただし、**実用的な演出**であること。
- （Claude の整理）**画面に出るものは、録画を始める前に操作する人が確かめる必要のあること、に限る。** 見栄えのための動きは入れない。
- 案: 収録前の点検の手順を、そのまま見せる。

| 手順 | 画面に出るもの | 何を確かめているか |
|---|---|---|
| 1. カメラを開く | 16:9 の全体の映像。最初の数フレームは自動露出が落ち着かず、明るさが揺れる | カメラが動いているか |
| 2. 構図とトリミング | 顔の検出枠と、切り抜く範囲の四角。決まると、カメラの窓がその範囲に切り替わる | 顔が画面に収まっているか。トリミングの理由もここで見せられる |
| 3. 顔の特徴点 | 目、虹彩、口の点。頭の向きの軸 | 表情と視線を追えるか |
| 4. 視線の較正 | 「画面のこの点を見てください」の手順。少女には通じないので、**較正は未完了のまま**になる | 視線の推定の信頼度。1日目は低いまま、という制約が手順から自然に生まれる |
| 5. 姿勢（骨格） | 肩、肘、手首、手指の点と線 | 腕や手が画面に入っているか。机の下に隠れた手は信頼度が低く出る |
| 6. 音声 | マイクの音量、部屋の雑音（30秒ほど何も話さずに録る「ルームトーン」）、アクリル板越しで高い音が弱まる、という注記 | 音が録れているか。雑音の基準 |
| 7. 同期 | 手を叩いて、音の波形と映像の動きを合わせる | 音声と映像のずれ |

- 少女の反応を挟める: 同期のために手を叩く主人公の動作が、少女には儀式の所作に見えるかもしれない（実用の動作を、儀式と取り違える）。
- 描画の色や文字は、使っているライブラリ（MediaPipe や OpenFace など）の初期の描画スタイルに従う。実機で確認してから決める。
- 実在の追跡ソフトは、止まっている顔でも点がわずかに揺れる。この揺れも再現する。

#### 技術メモ

- 点の位置は、立ち絵の差分ごとにデータとして持つ（顔、目、虹彩、肩、肘、手首、手指）。
- 実写向けの検出器（MediaPipe など）は、アニメ調の絵ではうまく検出できないことが多い（確度中〜高）。
  → アニメ調の顔に対応した検出器を試すか、簡単な Python の道具で手作業で点を打つ。

### アイコン

- 12×12 の1色のドット絵で自作する。既存のアイコン集は使わない（統一のためと、モダンなウェブ風の線画を避けるため）。
- 必要になった機能にだけ付ける。現在: cam（録画）、mic（音量）、gpu（使用率）、usb（道具の搬入）、netoff（切断）。

## 面接以外の場面（案）

オーナー: 移動や会話の場面は、エースコンバットや ARMORED CORE VI の、ミッションの合間のブリーフィングに近い雰囲気。もう少し緩くてもいい。
**同じシステムでそれ以外のこともできるか**を、選択の基準に入れる。

### 参考の整理（Claude）

- ARMORED CORE VI のブリーフィング: 依頼主の紋章や簡素な図の上に、音声と字幕だけ。登場人物の顔はほぼ出ない（確度中〜高）。
- エースコンバット7: 地図の上で目標や経路が動き、語りと字幕が付く。

### 案: 1つの合成の仕組みと、場面ごとの配置

画面を4つの層で組み、場面ごとに配置（プリセット）を切り替える。面接の画面も、配置の1つにすぎない。

| 層 | 中身 |
|---|---|
| 背景 | 画像、暗く落とした写真風の背景、図面や地図 |
| 資料 | 窓に入った資料（仮想マシン、組織のブリーフィング資料、報告書） |
| 文字 | 字幕、会話（名前＋台詞）、全画面の地の文（NVL） |
| 重ね表示 | 録画の HUD、特徴点、場面の見出し |

| 場面 | 配置 |
|---|---|
| 面接 | 仮想マシンのデスクトップ（これまでの検討どおり） |
| 移動（車内など） | 暗い背景＋場面の見出し＋会話。地の文が長いところは全画面の地の文 |
| ブリーフィング | 組織の資料（窓）＋リーダーの説明（会話） |
| 食堂、廊下、宿 | 暗い背景＋会話か地の文 |
| 1日の終わり | リーダーの報告書（資料） |
| 少女の側の場面（あれば） | 少女の言語の文字列に、その時点で解読できている層だけを重ねる |

### 場面の見出し

- 例: `2026-10-15 07:42 / 首都高速 / 社用車の後部座席`
- フィールドワークの記録の冒頭に、日時、場所、参加者を書く習慣がある。それに合わせた形にすれば、見出しの文字にも出どころが付く。

### 組織の資料はコンサルの資料の見た目

- リーダーは人事系のコンサルなので、ブリーフィング資料は会社の資料のテンプレート（表紙、目的、制約、期限、禁止事項）になる。
- 「目的: 異言語の解読」「期限: 7日」「禁止事項: インフォーマントに日本語を教えないこと」が、会社のスライドの体裁で並ぶ。
- 仮想マシンの無骨さとも、Gradio のモダンさとも違う、もう1つの出どころの層になる（チグハグさのルールの範囲内）。

### チームの顔は出さない（案）

- 顔の画像を持つのは少女だけにする。リーダーとエンジニアは名前と話し方だけで描く（「話し方で人物を作る」方針とも合う）。
- 例外は、冒頭のルームミラー越しのリーダーの目元だけ、のように絞る。
- 利点: 画像の素材が大幅に減る。NovelAI での人物の一貫性の問題も減る。プレイヤーがじっくり見る顔は少女の顔だけ、という主題とも合う。
- オーナー案: **入館証の顔写真か、アイコンで出してもよい。**
  - （Claude 補足）入館証なら、写真が小さく、正面で、平たい照明の証明写真になる。素材の一貫性を保ちやすく、画面に出る理由もある。
  - 入館証の文字にも出どころが付く: 氏名、所属（組織の表向きの社名）、番号、有効期限、バーコード。
  - 証明写真で人物を描ける: リーダーの硬い微笑み、エンジニアの気の抜けた写真、など。
  - 主人公の入館証は、性別を明かさないために写真を見せない（写真の欄が指で隠れている、写真は後日交付、など）。

## 面接画面の見本と、語の掘り下げ（案）

- 見本: `mock/interview.html`（生成元 `mock/src/interview.template.html`、組み立ては `python mock/src/build.py <テンプレート> <出力先>`）
- 仮想マシンの外（記録されないもの）は、仮想マシンと違う書体と色にする: 内省は明朝体の帯、通信はイヤホンのアイコンと入館証の写真の欄。
- 語の掘り下げは3種類:
  - **思考**（一回だけ）: その場面の内省の続き。台本に場面専用に書く。
  - **学部のノート**（辞書）: 主人公の学部時代の言語学概論のノート。一度書けば使い回せる。若い頃の記述と、今の赤字の追記が並ぶ。古い記述が、主人公の素朴な概念の出どころになる。
  - **通信**（イヤホン越し）: リーダーとエンジニア。語ではなく状況に結びつく。リーダーの通信は、進捗の管理とヒントを兼ねられる。
- 費用: 仕組みは Claude の作業で1日弱。高いのは文章（ノート1項目 100〜300字、第1話で 20〜40項目程度）。
- 吹き出しは、読んでいる内省の行を隠さないよう、内省の帯のすぐ上に開く。入れ子は親の横に開く。
- 窓の境目: 枠線 2px と隙間 6px（理由は machine-spec.md）。
- 内省の帯は消さない（案）。3つの状態:
  - 内省: 文章が流れる。
  - 作業メモ（待機中）: 新しい内省がないとき、主人公の頭の中の作業メモ（いまの仮説、次に試すこと）を出す。目的の提示を兼ねる。
  - 1行に畳む（分析中）: 道具を触っている間。帯は仮想マシンの上に重なっているので、畳んでも下の画面が見える。
- 学部のノート: 吹き出しから「ノートを開く」で、その回の見開きが開く。左に15回の目次。シラバスは notes-syllabus.md。
