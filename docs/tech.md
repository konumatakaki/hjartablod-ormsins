# 技術の選定（案）

必須条件（オーナー）: **ブラウザ上で、手間をかけずに遊べる。**

## 要件の整理

これまでの決定から出てくる要件:

| 要件 | 出どころ |
|---|---|
| インストール不要、すぐに起動する | 必須条件 |
| 画面は固定解像度（暫定 1280×720）を拡大縮小 | ui.md |
| 窓を並べたデスクトップ風の UI（dwm 風のタイル） | ui.md、design-rules.md |
| 大量の日本語テキスト、ルビ `|漢字《よみ》`、入れ子の用語注釈 | premises.md、style.md |
| 字幕が表記の層に応じて変わる（███ → IPA → 転写 → グロス） | ui.md |
| 立ち絵と差分（目線、手振り）、カメラ風のフィルター | ui.md |
| 図（スペクトル、MFCC）、精度のバー | mechanics.md |
| ミニゲーム（リズム、仕分け、並べ替え、ドラッグ） | mechanics.md |
| 音声（少女の声）と効果音 | open-questions.md |
| セーブとロード | ノベルゲームとして当然 |
| オーナーが、コードを触らずに台本や用語集を編集できる | premises.md |
| 半月後、オーナーだけでも内容を書き足し続けられる | premises.md |
| 無料で公開する | premises.md |

## 候補の比較

| 候補 | 良い点 | 悪い点 |
|---|---|---|
| **自作のウェブアプリ（HTML、CSS、TypeScript）** | デスクトップ風の UI、ルビ、注釈、日本語の改行はブラウザが最も得意。見本（mock）をそのまま発展させられる。軽く、起動が速い | ノベルゲームの基本機能（進行、セーブ、既読、ログ）を自分で作る必要がある |
| Ren'Py（ウェブ書き出し） | ノベルゲームの機能が揃っている。台本が Python 風で、オーナーに馴染みがある | ウェブ版は起動が重い。窓を並べた UI や、図やミニゲームを作り込むのが不得手 |
| ティラノスクリプト | 日本のウェブ向けノベルゲームの定番。タグで台本を書ける | 独自の UI（デスクトップ風、ミニゲーム）は拡張で無理をすることになる |
| Godot、Unity（ウェブ書き出し） | ミニゲームには強い | 起動が重い。日本語の文字組み、ルビ、入力まわりで苦労する。今回の UI には過剰 |

## 推し: 自作のウェブアプリ＋ink

### 構成

| 部分 | 使うもの | 理由 |
|---|---|---|
| 画面と操作 | TypeScript、Preact（React 互換の軽量ライブラリ） | 窓の UI は HTML と CSS が最も得意。Preact は小さく、書き方が React と同じなので、後で別の人や AI が触るときも分かりやすい |
| 台本の進行 | **ink**（inkle 社のスクリプト言語）と、その JavaScript 版 inkjs | 分岐、変数、選択肢、セーブ（状態の保存）が揃っている。専用エディタ Inky で、台本だけを試し読みできる。**言語解読ゲームの『Heaven's Vault』は、この ink で書かれている** |
| 演出の指示 | ink のタグ（例: `# cam: 正面 / 目線: 下`） | 台本の中に、立ち絵や道具の指示を書ける |
| 図 | Canvas | スペクトルや MFCC を描く |
| 音 | Web Audio | 少女の声、効果音 |
| セーブ | ブラウザの保存領域（localStorage）＋ファイルへの書き出し | ink の状態はそのまま文字列にできる |
| ビルド | Vite | 最終的にはただの静的ファイル（HTML、JS、画像）になる |
| 公開 | itch.io（HTML5 ゲームとして無料公開）と GitHub Pages | どちらも無料。itch.io は見つけてもらいやすい |
| 確認 | Playwright（この作業環境に入っている） | 画面のスクリーンショットを自動で撮り、design-rules.md のチェックに使う |

### 内容とエンジンを分ける

- **エンジン**（TypeScript）: 私が作る。変更にはビルドが要る。
- **内容**（台本、用語集、語彙、表記の層のデータ、画像、音声）: テキストファイルと素材のフォルダ。ゲームの起動時に読み込む。
  → オーナーは、内容のファイルを書き換えて、ブラウザを再読み込みするだけで確認できる。ビルドは要らない。
- 手元で確認するには `python -m http.server` で十分（Python があれば動く）。
- 内容の検査（用語集の参照切れ、ルビの書式の誤りなど）は、Python のスクリプトで書く。オーナーが読める言語にしておく。

### 台本の書き方のイメージ（ink）

```ink
=== day1_first_contact ===
# cam: 正面 / 表情: 真顔
私は|椅子《いす》に座り直した。インフォーマントの前では、まず姿勢から。
* [見せる: 絵カード「パンを食べる人」]
    # show_card: bread
    # utter: g_001
    少女は絵を見て、両手を胸の前で合わせた。
    -> bread_reaction
* [待つ]
    -> wait
```

ルビ `|漢字《よみ》` と用語の印は、ink の文字列の中にそのまま書き、表示のときにエンジンが変換する。

## 未決

- スマホやタブレットにどこまで対応するか（注釈のタップ操作、画面の縮小）。
- 固定解像度を 1280×720 にするか 1920×1080 にするか（文字のくっきり具合と、素材の大きさに関わる）。
- 逆転裁判のような失敗のペナルティ（体力ゲージなど）を持つか。状態の設計に関わる。
