# 道具のネタ帳

時代は現代くらい。ゲーム内の道具は、現実に存在する道具（またはその組み合わせ）を元ネタにする。
エンジニアがヴァイブコーディングでつなぎ合わせて作った、という体裁。**すべて例。**

## 現代の道具にできること（オーナー）

- 万能の翻訳 AI は出せない。
- 方向性さえ決めれば、それなりの「言語カード」を出せる。
- パターンが分かっていれば、音声から構文木を自動で作れる（精度は分からない）。

## 現代の道具の性質（Claude の整理）

**現代の道具は「仮説を増幅する装置」として扱う。**
仮説（方向性やパターン）を入れると、それに沿った出力を大量に、自信ありげに出す。
仮説が間違っていれば、出力も一貫して間違う。

- 概念を獲得すると、その概念を入力として使う道具が動き出す。
- 間違った仮説で動かした道具は、もっともらしく間違った証拠を出す。それに気づくことが矛盾の発見になる。

「概念の獲得 = 道具の表示の解像度が上がる」（mechanics.md）とも同じ構造。

## 現実の元ネタ

確度は特に書いていなければ高。

| ゲーム内の道具 | 現実の元ネタ | 必要な入力（仮説） | 出力と、ありがちな失敗 |
|---|---|---|---|
| 言語判定 | Whisper、Meta MMS の言語判定（数千言語に対応） | なし | 知らない言語でも、既知の言語に自信満々で振り分ける |
| 音声の書き起こし | Whisper などの音声認識 | 言語の指定 | 知らない言語を、既知の言語の単語ででたらめに書き起こす |
| 汎用の音の認識（IPA） | Allosaurus、wav2vec2 系の音素認識モデル | なし | 未知の言語でも IPA の候補を出すが、かなり間違える（精度は確度中） |
| ピッチ・フォルマント解析 | Praat（とその Python 版 Parselmouth） | なし | 数値は正確。解釈は人間がする |
| 発話と文字の位置合わせ | Montreal Forced Aligner など | 転写と音素の一覧 | 音素の一覧が間違っていると、ずれる |
| 形態素の自動分割 | Morfessor（教師なし学習） | コーパス | 統計的にもっともらしい切れ目を出す。意味とは無関係 |
| グロスと辞書の管理 | SIL の FLEx（FieldWorks）。フィールド言語学の定番 | 形態論の規則と語彙 | 規則を入れると半自動でグロスを付ける。規則が間違えば一貫して間違う |
| 構文木の自動生成 | 音声認識と構文解析器、または LLM の組み合わせ | 語順や形態素のパターン | パターンが分かれば出せる。精度は不明 |
| 文法書からの翻訳 | LLM。Kalamang 語の文法書1冊だけで翻訳させる研究（MTOB） | 文法の概要と辞書 | 流暢で、それなりに当たり、自信ありげに外れる |
| 表情・姿勢の解析 | MediaPipe、OpenFace（Ekman の表情の分類体系 FACS の動きの単位を出す） | なし | 動きの検出は正確。感情の解釈は文化差を無視する |
| 多層の注釈 | ELAN（映像・音声に複数の層の注釈を付ける） | なし | 道具というより、すべての層を並べる作業台 |
